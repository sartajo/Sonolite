# Sonolite
A small, open-source ultrasound device built to send sound pulses, receive echoes, and turn them into basic imaging data.

# Update (05/2026):  
Our Setup:
- Picoscope 2204A (Acts as our function Generator and Scope + ADC)
- Analog Pulser Board (Ultrasonic pulser + RX receive chain)
- Low Pass filter
- Ultrasonic PreAmplifier
- Single Element Transducer (Ours was custom-built)
- Teensy 4.0 + Micro Servo (used to move the transducer across 4cm)
- x64 PC running Linux (The picoSDK we used requires an x64 system)

Steps to download: (Note* we used a Linux system; however, the SDK seems to be available for Mac and Windows as well)
- clone the SDK repo for C support: https://github.com/picotech/picosdk-c-examples
- Build the corresponding files for your Picoscope model (Our firmware/code is designed to run on the 2000 series)
- Copy over the Python and C scripts (Located under: ps2000/linux-build-files)
  
        - image_constructor.py (Image construction algorithm+ Echo tracking)
        - sonolite_gui.py (Main GUI)
        - debug.py (Can use this script to view individual waveforms of scans)
        - scan_controller.c (Main control script, triggers pico signal + capture, triggers servo movement, and triggers image reconstruction)
        - servo_step.py (Script used to move around the servo by a certain increment)
        - pulse_capture_combo.c (Debug script; this script turns on the signal and allows for manual captures)
        - Additionally, copy firmware over from "ps2000/Teensy_Sonolite_software" and load onto teensy.

All software is designed to run with our corresponding hardware. Feel free to try and play around with different hardware and software setups.

Our pipeline begins with a 5 kHz, 2 Vpp excitation signal generated by the AWG of the PicoScope 2204A, which drives the ultrasonic pulser board to energize the transducer and emit acoustic pulses into the medium. The transducer is translated linearly via a motorized servo mechanism to acquire spatially distributed A-scans. The pulser board’s integrated receive chain captures returning echoes, which are then amplified using an ultrasonic preamplifier and filtered through a low-pass stage for noise suppression. The conditioned analog signal is subsequently digitized by the PicoScope 2204A for downstream signal processing and image reconstruction.

Our software pipeline interfaces with the PicoScope 2204A using the PicoSDK, with a C control script responsible for configuring acquisition parameters and triggering the excitation signal. The script manages data capture directly from the PicoScope’s ADC, recording each acquired A-scan and exporting it as an individual CSV file containing time and corresponding voltage samples. Concurrently, during acquisition, the control script invokes a Python process that communicates with a Teensy microcontroller via Pyserial to issue commands to a preloaded control script. This script drives a servo system that converts 180° rotational motion into linear translation through a linear actuator, enabling spatially distributed data capture.

Once acquisition is complete, the control script triggers the image reconstruction pipeline, implemented in Python. The script loads each captured A-scan (CSV), aligns signals by detecting the transmit pulse, and suppresses early-time artifacts such as ringdown. A time-of-flight window is then applied to isolate relevant echo data, which is converted to an amplitude envelope using the Hilbert transform. The resulting signals are normalized, thresholded, and log-compressed to generate grayscale intensity values. Multiple processed A-scans are stacked to reconstruct a 2D B-mode image. Additionally, the script identifies and tracks the dominant reflector across scans, producing both a standard image and a hybrid visualization with depth tracking.

# Update (02/2026):  
This document outlines the basic hardware setup and software processing pipeline used to generate a single-element ultrasound B-scan image using a custom pulser board, a PicoScope 2204A, and MATLAB. 

## 1. Hardware Setup
The system operates similarly to the previous step, but with the addition of the pulser. The DC power supply feeds the pulser, and pulser is connected to the transducer, and also has Rx/Tx with the picoscope. The picoscope is then connected to the MacBook/laptop, which runs Matlab and picoscope scope, and the image is generated in Matlab. The system operates in a pulse-echo configuration where the PicoScope acts as the master clock, triggering a custom high-voltage pulser board to fire the transducer.

**Connections:**
* **PicoScope AWG (Gen) $\rightarrow$ Pulser Board (Trigger In / X1):** Sends a low-voltage square wave to wake up the board and command it to fire.
* **Pulser Board (RF Out / X4) $\rightarrow$ PicoScope Channel A:** Sends the amplified acoustic echo back to the oscilloscope.
* **Pulser Board (X2) $\rightarrow$ Transducer:** The physical connection to the piezoelectric crystal.
* **DC Power Supply $\rightarrow$ Pulser Board:** Provides the necessary high voltage for the board to generate the transmission pulse (the "Main Bang").

## 2. PicoScope 7 Configuration & Data Capture
To view and capture the raw RF (Radio Frequency) acoustic waves, the PicoScope 7 software is configured as follows:

* **Generator (AWG):** * Type: Square Wave
  * Frequency: 1 kHz (fires the transducer 1,000 times per second)
  * Amplitude: 1 V
  * Offset: 1 V (Creates a clean 0V to +2V logic pulse)
* **Timebase (X-Axis):** Set to `5 µs/div` to zoom in on the fast-moving acoustic echoes.
* **Channel A (Y-Axis):** Set to `±1 V` or `±2 V` depending on the echo strength.
* **Trigger:** Set to `Auto` or `Repeat`, Source `Channel A`, with a rising edge threshold of `~400 mV` to freeze the waveform on the screen.

**Exporting Data:**
Once an echo is acquired (e.g., bouncing off the bottom of a water cup), the waveform is paused and saved as a standard `.txt` file. This exports the raw `Time` and `Channel A Voltage` arrays.

## 3. MATLAB Image Generation
An ultrasound image (B-scan) is created by stacking multiple 1D acoustic recordings (A-scans) side-by-side. The raw RF voltage data is converted into grayscale pixel intensity through envelope detection, followed by normalization, depth-dependent gain compensation (TGC), logarithmic compression to reduce dynamic range, and contrast adjustment before grayscale mapping for final image display.
